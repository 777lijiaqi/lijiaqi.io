I2C子系统：I2C总线设备模型
- MPU6050与DHT20传感器驱动

目标硬件：野火 i.MX6ULL Pro 底板 (MCIMX6Y2CVM08AB / Cortex-A7)

目标内核：Linux 4.1.15

通信总线：I2C1 控制器 (MPU6050: 从机地址 0x68 / DHT20: 从机地址 0x38)

本文档基于 Linux 2.6+ / 4.x / 5.x 现代内核标准，全面系统地总结了 Linux I2C 子系统的核心分层架构、设备树（Device Tree）节点拓扑、驱动全生命周期流转、i2c_msg / i2c_transfer 核心通信时序机制、面向对象双向绑定模式，以及 全套 I2C 核心 API 详解与工程避坑指南。

一、Linux I2C 子系统三层架构全景图

Linux 内核将 I2C 子系统高度抽象解耦为三层架构：

┌─────────────────────────────────────────────────────────────────────────┐
│                    Linux I2C 子系统三层体系架构                          │
└─────────────────────────────────────────────────────────────────────────┘

  【层级 3：I2C 设备驱动层 (I2C Device Driver)】── (👉 驱动工程师编写 👈)
    * 代表具体从机芯片（如 MPU6050, AT24C02, 触摸屏 GT9147）的控制逻辑；
    * 核心结构体：struct i2c_driver, struct i2c_client；
    * 将底层 I2C 数据封装为字符设备（/dev/mpu6050）、Input 设备或 IIO 传感器设备。
                          │
                          ▼ (通过标准 API 通信: i2c_transfer)
  【层级 2：I2C 核心层 (I2C Core)】────────────── (Linux 内核官方维护: drivers/i2c/i2c-core.c)
    * 提供统一的总线管理、适配器注册/注销、设备与驱动匹配算法；
    * 提供通用的数据收发总入口函数：i2c_transfer()、i2c_smbus_xfer()。
                          │
                          ▼ (调用底层算法: adap->algo->master_xfer)
  【层级 1：I2C 控制器/适配器驱动层 (I2C Adapter)】 (芯片原厂编写: 如 drivers/i2c/busses/i2c-imx.c)
    * 代表 SoC 片上的 I2C 硬件控制器（如 i.MX6ULL 的 I2C1 控制器，基地址 0x021A0000）；
    * 核心结构体：struct i2c_adapter, struct i2c_algorithm；
    * 负责操控底层物理寄存器产生 I2C 起始信号（START）、停止信号（STOP）、时钟线（SCL）与应答位（ACK）。

2. 四大核心结构体关系图

结构体 代表的物理/逻辑实体 包含的关键字段 产生时机
struct i2c_adapter SoC 内部的 I2C 硬件控制器 nr (总线号 0,1), algo (底层时序算法), dev 系统启动时原厂驱动注册生成
struct i2c_client 挂在总线上的某一个物理从机设备 addr (7位从机地址 0x68), name, adapter, dev 内核解析设备树子节点后自动生成
struct i2c_driver 管理该类从机设备的通用驱动程序 probe, remove, id_table, driver.of_match_table 模块加载 module_i2c_driver 注册
struct i2c_msg 一次完整通信的数据包（帧） addr (从机地址), flags (读/写), len (长度), buf (数据) 发起 i2c_transfer 临时构造

二、设备树 (Device Tree) 中 I2C 节点配置规范

1. I2C 控制器节点 (&i2c1)

I2C 从机必须挂在对应的 I2C 控制器节点内部，作为其子节点存在：

/* 打开 imx6ull-rkljq.dts */
&i2c1 {
    clock-frequency = <100000>;      /* I2C 标准速率: 100kHz (快速模式可填 400000) */
    pinctrl-names = "default";
    pinctrl-0 = <&pinctrl_i2c1>;     /* SCL 与 SDA 引脚复用与电气属性组 */
    status = "okay";

    /* ================= 2. I2C 从机设备子节点 ================= */
    mpu6050@68 {
        compatible = "fsl,mpu6050";  /* 与驱动中 of_device_id.compatible 必须一字不差 */
        reg = <0x68>;                /* MPU6050 的 7 位 I2C 物理硬件从机地址 */
        status = "okay";
    }; /* ⚠️ 注意：节点花括号末尾必须带分号 ';' */
};

3. 设备树节点在 /proc/device-tree 的映射拓扑

因为 i2c1 是 SoC 片内控制器，内核解析后生成的树状目录为：

/proc/device-tree/soc/aips-bus@02100000/i2c@021a0000/mpu6050@68/
  ├── compatible  (内容: "fsl,mpu6050")
  ├── reg         (内容: 0x00000068)
  └── status      (内容: "okay")

三、I2C 驱动全生命周期流转与双向绑定机制

1. 驱动全生命周期流转图

【阶段一：系统上电与从机实体生成 (Booting)】
  U-Boot 传递 .dtb ──► 内核解析 &i2c1 节点下的 mpu6050@68
  I2C Core 在内存中自动创建 struct i2c_client 实体 (addr=0x68, 挂在 i2c-0 适配器下)
  （此时硬件设备就绪，在 /sys/bus/i2c/devices/ 生成 0-0068 目录）

【阶段二：驱动加载与探测 (insmod mpu6050.ko)】
  module_i2c_driver() ──► i2c_add_driver(&mpu6050_driver)
          │
          ▼
  I2C 总线遍历挂载的 client，比对 compatible 属性
          │ (匹配成功 Match!)
          ▼
  内核自动调用 mpu6050_probe(client, id)：
    ├─► 1. devm_kzalloc() 动态申请自定义大结构体 struct i2c_dev *mpu6050
    ├─► 2. 双向指针绑定:
    │        mpu6050->client = client;              (供 read/write 通信使用)
    │        i2c_set_clientdata(client, mpu6050);   (供 remove 取回大结构体)
    ├─► 3. alloc_chrdev_region() 动态申请主次设备号
    ├─► 4. cdev_init() + cdev_add() 注册字符设备
    ├─► 5. class_create() + device_create() 生成 /dev/mpu6050
    └─► 6. 调用 mpu6050_init() 发送 I2C 时序唤醒芯片并配置量程

【阶段三：用户态数据读写 (交互阶段)】
  用户程序执行 read(fd, buf, 14)：
    ├─► mpu6050_open() : container_of 从 inode 反推 mpu6050，存入 filp->private_data
    └─► mpu6050_read() : 取出 private_data，调用 i2c_read_mpu6050() 发送 2 个 msg 复合时序
                         读取 14 字节并通过 copy_to_user 传回用户空间！

【阶段四：驱动卸载 (rmmod mpu6050)】
  i2c_del_driver() ──► 触发 mpu6050_remove(client)：
    ├─► 1. struct i2c_dev *mpu6050 = i2c_get_clientdata(client); (瞬间取回)
    ├─► 2. device_destroy() 销毁 /dev/mpu6050
    ├─► 3. class_destroy() 销毁 /sys/class/mpu6050
    ├─► 4. cdev_del() 注销字符设备
    └─► 5. unregister_chrdev_region() 释放设备号 (内存由 devm_kzalloc 自动回收)

2. 双向指针绑定与跨函数数据流转深度解析

       【自定义大结构体 (堆内存 0xC0508000)】           【内核 I2C 从设备对象 (0xDEADC000)】
        struct i2c_dev (mpu6050)                     struct i2c_client (client)
      ┌───────────────────────────┐                ┌───────────────────────────┐
      │ struct cdev cdev;         │                │ struct i2c_adapter *adap; │
      │ dev_t dev;                │                │ u16 addr; (0x68)          │
      │ ...                       │                │ ...                       │
      │                           │                │                           │
      │ struct i2c_client *client;│ ─────────────► │                           │
      │ (第一步: 供 read 找到 I2C) │                │                           │
      │                           │                │ void *driver_data;        │
      │                           │ ◄───────────── │ (第二步: 供 remove 找大结构体)│
      └───────────────────────────┘                └───────────────────────────┘
  • mpu6050->client = client;：让 read() 函数通过大结构体拿到硬件通信指针，调用 i2c_transfer(mpu6050->client->adapter, ...)；
  • i2c_set_clientdata(client, mpu6050);：将大结构体地址保存在 client->dev.driver_data 中，让 remove(client) 能够通过 i2c_get_clientdata(client) 找回自己的结构体进行注销；
  • 彻底消除全局变量：即使系统接入 10 个 MPU6050，各个设备的内存与 client 一对一绑定，实现纯粹的面向对象并发支持！

四、I2C 通信时序与万能传输协议 (i2c_msg / i2c_transfer)

1. struct i2c_msg 核心成员深度解析

struct i2c_msg {
    __u16 addr;   /* 从机 7 位物理地址 (如 0x68，严禁手动左移拼读写位！) */
    __u16 flags;  /* 传输控制标志: 0 表示写操作, I2C_M_RD (0x0001) 表示读操作 */
    __u16 len;    /* 本次 msg 发送/接收的有效字节数 */
    __u8 *buf;    /* 数据缓冲区首地址指针 */
};

2. 单次写寄存器时序 (1 个 msg)

  • 应用场景：向从机芯片的某个寄存器写入配置数值（如向 0x6B 写入 0x00 唤醒芯片）。
  • 时序图解： 
    [START] ──► [从机地址(0x68) + 写位(0)] ──► [寄存器地址(0x6B)] ──► [写入数据(0x00)] ──► [STOP]
  • 标准驱动代码实现： 
    static int i2c_write_reg(struct i2c_client *client, u8 reg, u8 data)
{
    u8 buf[2] = {reg, data}; /* 连续发送: [寄存器地址, 写入值] */
    struct i2c_msg msg;

    msg.addr  = client->addr; /* 7 位物理地址 (0x68) */
    msg.flags = 0;            /* 0 代表写操作 */
    msg.len   = 2;            /* 传输 2 字节 */
    msg.buf   = buf;

    /* 传输 1 个 msg，成功返回 1，转换为 0 表示成功 */
    return (i2c_transfer(client->adapter, &msg, 1) == 1) ? 0 : -EIO;
}

3. 复合读寄存器时序 (Repeated START / 2 个 msg)

  • 应用场景：绝大多数“多寄存器芯片”（MPU6050、EEPROM），读数据时必须先写目标寄存器地址，紧接着以重复起始信号读取数据。
  • 时序图解： 
    [START] ──► [从机地址+写(0)] ──► [目标寄存器(0x3B)] ──► [REPEATED START] ──► [从机地址+读(1)] ──► [连续读14字节...] ──► [STOP]
└────────────────── msg[0]: 写寄存器地址 ──────────────────┘  └─────────────────── msg[1]: 连续读数据 ───────────────────┘
  • 标准驱动代码实现： 
    static int i2c_read_regs(struct i2c_client *client, u8 reg, void *data, u32 length)
{
    struct i2c_msg msgs[2];

    /* 消息 0: 向从机写入要读取的目标寄存器起始地址 (写操作) */
    msgs[0].addr  = client->addr;
    msgs[0].flags = 0;
    msgs[0].len   = 1;
    msgs[0].buf   = &reg;

    /* 消息 1: 连续读取 length 字节数据 (读操作) */
    msgs[1].addr  = client->addr;
    msgs[1].flags = I2C_M_RD; /* 👈 必须指定 I2C_M_RD 读标志 */
    msgs[1].len   = length;
    msgs[1].buf   = (u8 *)data;

    /* ⚠️ 核心注意：发送了 2 个 msg，全部成功时 i2c_transfer 返回 2！ */
    return (i2c_transfer(client->adapter, msgs, 2) == 2) ? 0 : -EIO;  API 02 详解 ↗
}

4. 单次纯读时序 (1 个 msg)

  • 应用场景：无寄存器寻址概念的简单传感器（如光照传感器 BH1750、部分 ADC）。
  • 标准代码实现： 
    static int i2c_pure_read(struct i2c_client *client, void *data, u32 length)
{
    struct i2c_msg msg;

    msg.addr  = client->addr;
    msg.flags = I2C_M_RD;
    msg.len   = length;
    msg.buf   = (u8 *)data;

    return (i2c_transfer(client->adapter, &msg, 1) == 1) ? 0 : -EIO;
}

五、现代 I2C 字符设备驱动黄金源码模板 (Golden Template)

以下为标准的 Linux I2C 字符设备驱动完整源码模板，具备面向对象封装、资源自动托管、严格时序与异常回滚：

#include <linux/init.h>
#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/types.h>
#include <linux/errno.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/device.h>
#include <linux/uaccess.h>
#include <linux/i2c.h>
#include <linux/of.h>
#include <linux/of_device.h>
#include <linux/slab.h>
#include <linux/delay.h>

#define DEV_NAME               "mpu6050"
#define MPU6050_ACCEL_XOUT_H   0x3B
#define MPU6050_PWR_MGMT_1     0x6B
#define MPU6050_WHO_AM_I       0x75

/* 1. 自定义设备结构体 */
struct mpu6050_dev {
    struct cdev cdev;
    dev_t devno;
    int major;
    struct class *class;
    struct device *node;
    struct i2c_client *client; /* 硬件通信句柄 */
};

/* 2. 底层 I2C 读写通信封装 */
static int i2c_write_mpu6050(struct i2c_client *client, u8 reg, u8 data)
{
    u8 buf[2] = {reg, data};
    struct i2c_msg msg = {
        .addr  = client->addr,
        .flags = 0,
        .len   = 2,
        .buf   = buf,
    };
    return (i2c_transfer(client->adapter, &msg, 1) == 1) ? 0 : -EIO;
}

static int i2c_read_mpu6050(struct i2c_client *client, u8 reg, void *data, u32 length)
{
    struct i2c_msg msgs[2] = {
        { .addr = client->addr, .flags = 0,        .len = 1,      .buf = &reg },
        { .addr = client->addr, .flags = I2C_M_RD, .len = length, .buf = (u8 *)data },
    };
    return (i2c_transfer(client->adapter, msgs, 2) == 2) ? 0 : -EIO;
}

/* 3. 硬件唤醒与初始化配置 */
static int mpu6050_hw_init(struct i2c_client *client)
{
    u8 id = 0;
    int ret;

    /* 复位芯片并等待就绪 */
    ret = i2c_write_mpu6050(client, MPU6050_PWR_MGMT_1, 0x80);
    if (ret < 0) return ret;
    msleep(100);

    /* 唤醒芯片并选择 PLL 稳定时钟 */
    ret = i2c_write_mpu6050(client, MPU6050_PWR_MGMT_1, 0x01);
    if (ret < 0) return ret;
    msleep(20);

    /* 验证芯片 ID */
    ret = i2c_read_mpu6050(client, MPU6050_WHO_AM_I, &id, 1);
    if (ret < 0) return ret;
    if (id != 0x68) {
        dev_err(&client->dev, "Invalid chip ID: 0x%02X (expected 0x68)!\n", id);
        return -ENODEV;
    }
    dev_info(&client->dev, "MPU6050 detected successfully! ID = 0x%02X\n", id);
    return 0;
}

/* 4. 文件操作集 (VFS 接口) */
static int mpu6050_open(struct inode *inode, struct file *filp)
{
    struct mpu6050_dev *mpu = container_of(inode->i_cdev, struct mpu6050_dev, cdev);
    filp->private_data = mpu;
    return 0;
}

static ssize_t mpu6050_read(struct file *filp, char __user *buf, size_t cnt, loff_t *loff)
{
    struct mpu6050_dev *mpu = (struct mpu6050_dev *)filp->private_data;
    u8 data[14];
    int ret;

    /* 实时读取 14 字节原始运动数据 */
    ret = i2c_read_mpu6050(mpu->client, MPU6050_ACCEL_XOUT_H, data, sizeof(data));
    if (ret < 0) {
        dev_err(&mpu->client->dev, "Read sensor data failed!\n");
        return -EIO;
    }

    if (copy_to_user(buf, data, sizeof(data)))  API 07 详解 ↗
        return -EFAULT;

    return sizeof(data);
}

static int mpu6050_release(struct inode *inode, struct file *filp)
{
    return 0;
}

static const struct file_operations mpu6050_fops = {
    .owner   = THIS_MODULE,
    .open    = mpu6050_open,
    .read    = mpu6050_read,
    .release = mpu6050_release,
};

/* 5. Probe 探测函数 */
static int mpu6050_probe(struct i2c_client *client, const struct i2c_device_id *id)
{
    struct mpu6050_dev *mpu;
    int ret;

    /* 5.1 动态分配大结构体 (自动垃圾回收) */
    mpu = devm_kzalloc(&client->dev, sizeof(*mpu), GFP_KERNEL);  API 05 详解 ↗
    if (!mpu) return -ENOMEM;

    /* 5.2 双向绑定 */
    mpu->client = client;
    i2c_set_clientdata(client, mpu);  API 03 详解 ↗

    /* 5.3 申请设备号与注册 cdev */
    ret = alloc_chrdev_region(&mpu->devno, 0, 1, DEV_NAME);
    if (ret < 0) {
        dev_err(&client->dev, "Alloc chrdev region failed!\n");  API 06 详解 ↗
        return ret;
    }
    mpu->major = MAJOR(mpu->devno);

    cdev_init(&mpu->cdev, &mpu6050_fops);
    mpu->cdev.owner = THIS_MODULE;
    ret = cdev_add(&mpu->cdev, mpu->devno, 1);
    if (ret < 0) {
        dev_err(&client->dev, "Add cdev failed!\n");
        goto unregister_devno;
    }

    /* 5.4 创建类与设备节点 /dev/mpu6050 */
    mpu->class = class_create(THIS_MODULE, DEV_NAME);
    if (IS_ERR(mpu->class)) {
        ret = PTR_ERR(mpu->class);
        goto del_cdev;
    }

    mpu->node = device_create(mpu->class, NULL, mpu->devno, NULL, DEV_NAME);
    if (IS_ERR(mpu->node)) {
        ret = PTR_ERR(mpu->node);
        goto destroy_class;
    }

    /* 5.5 初始化硬件 */
    ret = mpu6050_hw_init(client);
    if (ret < 0) {
        dev_err(&client->dev, "Hardware init failed!\n");
        goto destroy_device;
    }

    dev_info(&client->dev, "MPU6050 probe successfully!\n");
    return 0;

/* 瀑布式错误回滚 */
destroy_device:
    device_destroy(mpu->class, mpu->devno);
destroy_class:
    class_destroy(mpu->class);
del_cdev:
    cdev_del(&mpu->cdev);
unregister_devno:
    unregister_chrdev_region(mpu->devno, 1);
    return ret; /* ⚠️ 必须返回负数错误码！ */
}

/* 6. Remove 注销函数 */
static int mpu6050_remove(struct i2c_client *client)
{
    struct mpu6050_dev *mpu = i2c_get_clientdata(client);  API 04 详解 ↗

    device_destroy(mpu->class, mpu->devno);
    class_destroy(mpu->class);
    cdev_del(&mpu->cdev);
    unregister_chrdev_region(mpu->devno, 1);

    dev_info(&client->dev, "MPU6050 removed!\n");
    return 0;
}

/* 7. 匹配表与一键注册宏 */
static const struct i2c_device_id mpu6050_id[] = {
    { "fsl,mpu6050", 0 },
    { /* sentinel */ }
};
MODULE_DEVICE_TABLE(i2c, mpu6050_id);

static const struct of_device_id mpu6050_of_match[] = {
    { .compatible = "fsl,mpu6050" },
    { /* sentinel */ }
};
MODULE_DEVICE_TABLE(of, mpu6050_of_match);

static struct i2c_driver mpu6050_driver = {
    .probe    = mpu6050_probe,
    .remove   = mpu6050_remove,
    .id_table = mpu6050_id,
    .driver = {
        .name           = "mpu6050",
        .owner          = THIS_MODULE,
        .of_match_table = mpu6050_of_match,
    },
};

module_i2c_driver(mpu6050_driver);  API 01 详解 ↗

MODULE_LICENSE("GPL v2");

七、I2C 驱动开发高频避坑指南 (Top Pitfalls)

  1. i2c_msg.addr 严禁手动移位 ⚠️：
    • msg.addr 填的是纯 7 位从机地址（如 0x68），内核 I2C 硬件控制器在发送时会自动执行 (addr << 1) | 读写位。如果手动左移写成 0xD0，通信会彻底寻址失败！
  2. 复合读操作返回值必须比对 == 2 ⚠️：
    • 发送了 2 个 msg（写地址 + 读数据），i2c_transfer 成功时返回 2。误写成 == 1 会导致成功时误判为错误。
  3. 设备树 compatible 必须一字不差 ⚠️：
    • DTS 中的 compatible = "fsl,mpu6050"; 与 C 驱动中的 of_device_id.compatible 必须完全匹配（注意逗号后是否有空格）。
  4. 实时流式传感器 read() 严禁加 *loff 拦截 ⚠️：
    • 传感器属于无边界数据流设备，每次应用层 read() 都应实时采集最新数据。若加了 if (*loff > 0) return 0;，应用层的连续读取循环会在第 2 次直接卡死。
  5. probe() 错误回滚必须返回 ret ⚠️：
    • 错误回滚标签末尾必须写 return ret;，严禁写成 return 0;。
