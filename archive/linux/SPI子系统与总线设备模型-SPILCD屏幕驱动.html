SPI子系统：SPI总线设备模型
- SPI LCD屏幕驱动

目标硬件：野火 i.MX6ULL Pro 底板 (MCIMX6Y2CVM08AB / Cortex-A7)

目标内核：Linux 4.1.15

通信总线：ECSPI3 控制器 (最高通信速率 20MHz / ST7789V 240x240 RGB565 彩屏)

本文档基于 Linux 2.6+ / 4.x / 5.x 现代内核标准，全面系统地总结了 Linux SPI 子系统的核心体系架构、设备树 (Device Tree) 中 SPI 控制器与从机节点规范、spi_message 与 spi_transfer 核心通信时序机制、4线制 SPI LCD 屏幕硬件初始化与显存刷屏原理，以及 全套 Linux SPI 核心 API 全景解析与工程避坑指南。

一、Linux SPI 子系统体系架构全景图

Linux 内核将 SPI 驱动模型划分为三个高内聚、低耦合的标准层级：

┌─────────────────────────────────────────────────────────────────────────┐
│                    Linux SPI 子系统三层体系架构                          │
└─────────────────────────────────────────────────────────────────────────┘

  【层级 3：SPI 设备驱动层 (SPI Device Driver)】── (👉 驱动工程师编写 👈)
    * 代表具体从机芯片（如 SPI LCD 屏、W25Qxx Flash、SPI 传感器）的业务协议；
    * 核心结构体：struct spi_driver, struct spi_device；
    * 负责组装业务数据（如写入显存指令、寄存器读写），并向核心层发起数据收发请求。
                          │
                          ▼ (调用标准 API: spi_sync / spi_write)
  【层级 2：SPI 核心层 (SPI Core)】────────────── (Linux 内核维护: drivers/spi/spi.c)
    * 提供统一的 API 抽象，向上为驱动层提供接口，向下为控制器层管理通信队列；
    * 自动匹配设备树（DTS）节点与驱动，触发执行驱动的 probe(struct spi_device *spi)；
    * 管理传输队列与并发保护。
                          │
                          ▼ (调用 master->transfer_one_message)
  【层级 1：SPI 控制器驱动层 (SPI Master Driver)】 (芯片原厂维护: 如 drivers/spi/spi-imx.c)
    * 针对 SoC 内部硬件 SPI 控制器（如 i.MX6ULL 的 ECSPI1~ECSPI4）；
    * 核心结构体：struct spi_master / struct spi_controller；
    * 负责直接操作物理寄存器、DMA 搬运与硬件时钟分频，驱动物理引脚发送比特流。

二、设备树 (Device Tree) 中 SPI 节点配置规范

1. SPI 控制器节点 (&ecspi3)

&ecspi3 {
    pinctrl-names = "default";
    pinctrl-0 = <&pinctrl_ecspi3>;
    cs-gpios = <&gpio1 20 GPIO_ACTIVE_LOW>;
    status = "okay";

    /* SPI 从机设备子节点 */
    spi_screen: spi-screen@0 {
        compatible = "rkljq,spi-screen";
        reg = <0>;                               /* 对应 cs-gpios 索引 0 */
        spi-max-frequency = <20000000>;          /* 20 MHz 极速通信 */
        dc-gpios = <&gpio1 4 GPIO_ACTIVE_HIGH>;   /* 数据/命令切换引脚 */
        rst-gpios = <&gpio4 20 GPIO_ACTIVE_HIGH>; /* 硬件复位引脚 */
        status = "okay";
    };
};

三、4线制 SPI 彩屏硬件控制原理 (以 240x240 LCD 为例)

4线制 SPI 屏幕采用单向高速推挽总线：

  1. SCLK (时钟线)：硬件控制器产生极速时钟信号（本驱动设定为 20MHz）；
  2. MOSI (主机输出从机输入)：传输显存像素与指令字节；
  3. DC (Data/Command 选通引脚)：
    • 低电平 (0)：向屏幕芯片发送控制命令（如设置窗口、开显存）；
    • 高电平 (1)：向屏幕发送像素色彩数据（RGB565 颜色阵列）；
  4. RST (硬件复位引脚)：低电平脉冲复位屏幕内部控制器；
  5. CS (片选引脚)：低电平使能选通。

四、SPI 数据传输协议与通信时序 (spi_message / spi_transfer)

1. struct spi_transfer 与 struct spi_message

  • spi_transfer：单次物理连续传输块，指定发送缓冲区 tx_buf、接收缓冲区 rx_buf、数据长度 len、位宽与速度；
  • spi_message：传输事务单元，可以将多个 spi_transfer 串接在尾部，作为一个原子操作提交。
struct spi_message m;
struct spi_transfer xfer;

memset(&xfer, 0, sizeof(xfer));
xfer.tx_buf = buf;
xfer.len = total_bytes;

spi_message_init(&m);
spi_message_add_tail(&xfer, &m);
spi_sync(dev->spi_dev, &m);

五、工业级 SPI 屏幕驱动核心黄金源码剖析 (spi_lcd.c)

#include "spi_drv.h"

#define CMD_MODE    0
#define DATA_MODE   1

/* 1. SPI 发送命令与数据底层接口 */
static int spi_screen_write_cmd(struct spi_dev* dev, uint8_t* cmd, uint32_t len) {
    gpio_set_value(dev->dc_gpio, CMD_MODE);
    return spi_write(dev->spi_dev, cmd, len);
}

static int spi_screen_write_data(struct spi_dev* dev, uint8_t* data, uint32_t len) {
    gpio_set_value(dev->dc_gpio, DATA_MODE);
    return spi_write(dev->spi_dev, data, len);
}

/* 2. 屏幕窗口设定 (ST7789V 240x240 窗口裁切) */
static void spi_screen_set_window(struct spi_dev* dev, uint16_t x_start, uint16_t y_start, uint16_t x_end, uint16_t y_end) {
    uint8_t d_x[4] = { (uint8_t)(x_start >> 8), (uint8_t)(x_start & 0xFF), (uint8_t)(x_end >> 8), (uint8_t)(x_end & 0xFF) };
    uint8_t d_y[4] = { (uint8_t)(y_start >> 8), (uint8_t)(y_start & 0xFF), (uint8_t)(y_end >> 8), (uint8_t)(y_end & 0xFF) };

    lcd_write_cmd(dev, 0x2A);
    lcd_write_data_bytes(dev, d_x, 4);

    lcd_write_cmd(dev, 0x2B);
    lcd_write_data_bytes(dev, d_y, 4);

    lcd_write_cmd(dev, 0x2C);
}

/* 3. 全屏 115200 字节显存刷屏加速 (240 * 240 * 2 字节) */
static void spi_screen_clear(struct spi_dev* dev, uint16_t color) {
    int i;
    int total_bytes = 240 * 240 * 2; // 115200 bytes
    uint8_t* buf;
    struct spi_message m;
    struct spi_transfer xfer;

    buf = kmalloc(total_bytes, GFP_KERNEL);
    if (!buf) {
        dev_err(&dev->spi_dev->dev, "Failed to allocate 115200 bytes!
");
        return;
    }

    for (i = 0; i < 240 * 240; i++) {
        buf[2 * i]     = (uint8_t)(color >> 8);
        buf[2 * i + 1] = (uint8_t)(color & 0xFF);
    }

    spi_screen_set_window(dev, 0, 0, 239, 239);
    gpio_set_value(dev->dc_gpio, DATA_MODE);

    memset(&xfer, 0, sizeof(xfer));
    xfer.tx_buf = buf;
    xfer.len = total_bytes;

    spi_message_init(&m);
    spi_message_add_tail(&xfer, &m);
    spi_sync(dev->spi_dev, &m);

    kfree(buf);
}

六、Linux SPI 核心 API 全景百科全书

1. module_spi_driver / spi_register_driver

  • 函数原型：int spi_register_driver(struct spi_driver *sdrv);
  • 作用：向 Linux SPI 总线注册驱动对象，展开后完成内核模块初始化与注销挂载。

2. spi_sync

  • 函数原型：int spi_sync(struct spi_device *spi, struct spi_message *message);
  • 作用：同步阻塞提交 SPI 传输事务，等待底层硬件传输完成并返回。进程上下文安全。

3. spi_write

  • 函数原型：int spi_write(struct spi_device *spi, const void *buf, size_t len);
  • 作用：快捷发送单块连续缓冲区，底层自动封装单 spi_transfer 与 spi_message。

4. spi_set_drvdata / spi_get_drvdata

  • 作用：将自定义私有结构体指针绑定至 spi->dev.driver_data，实现驱动生命周期解耦。

七、SPI 驱动开发高频避坑指南 (Top Pitfalls)

  1. GCC 结构体赋值引发的 GOT 重定位错误 ⚠️：
    • 显存超大批量刷屏时，直接在内核驱动中使用 spi_write 宏可能会因为老版 GCC 内联结构体拷贝触发 _GLOBAL_OFFSET_TABLE_ 未定义符号；必须手动显式初始化 struct spi_transfer 并调用 spi_sync。
  2. DMA 缓存一致性与连续物理内存 ⚠️：
    • 大块显存传输建议使用 kmalloc(..., GFP_KERNEL) 申请连续虚拟与物理内存，杜绝使用栈内存做 SPI DMA 发送缓冲。
  3. DC 引脚电平切换的时序窗口 ⚠️：
    • 必须先将 DC 引脚切换为指定电平（gpio_set_value(dev->dc_gpio, ...)），再调用 spi_write 发送字节，否则会导致从机时钟边沿提前采样到错误的数据模式。
